# Data and Artifacts

[中文](DATA_AND_ARTIFACTS.md) | **English**

## Data type

All experimental data is program-generated and contains no user data, personal records, or restricted
third-party dataset. JSON and JSONL under `results/` record model configuration, random seeds, step-wise
task metrics, propagation diagnostics, intervention events, timing, and termination reasons.

## Directory roles

- `results/**/logs/*.jsonl`: largest, immutable per-step evidence.
- `results/**/runs/*.json`: per-run summaries.
- `results/**/manifest.json`: frozen configuration, environment, and run inventory.
- `results/*_analysis.json`: structured audits generated by analysis scripts.
- `docs/`: human-readable methodology, reports, and stop notes.
- `output/figures/`: publication PNG and editable SVG figures.
- `output/pdf/`: preprint PDF.
- `output/attachments/`: release-attachment policy; generated ZIP and SHA-256 files stay out of the
  main Git history.
- `paper/`: editable preprint source.
- `website/`: interactive explainer source; dependencies are excluded.

## Repository storage policy

After removing development intermediates, raw JSONL in the main candidate set totals about 185 MiB and
the largest single file is about 9 MiB, below GitHub's
100 MB single-file limit. A private research repository can version these frozen logs without Git LFS.
To prevent history inflation:

- completed JSONL files are never rewritten in place;
- analysis corrections create new derived results instead of altering raw trajectories;
- future artifacts above 50 MB per file move to a private GitHub Release or object storage;
- `node_modules`, caches, temporary PDF renders, and blog deployment copies are excluded.

## Invalid and stopped data

Actively stopped runs with interpretable mechanism or fixed-update evidence remain in the candidate set
with a stop audit. Pure smoke tests, superseded calibration, protocol-invalid pre-runs, and incomplete
trajectories without an independent conclusion remain in the ignored local archive; reports retain their
run identifiers, exclusion reasons, and necessary summaries. Neither category enters formal means,
win/loss counts, or significance summaries. Referenced negative evidence is not deleted.

## Privacy and machine metadata

Some manifests retain local backend, version, and absolute work paths for environment tracing. They may
remain during private collaboration. Before public release, generate sanitized copies that replace
personal paths with relative project paths without changing numeric results, then regenerate artifact
manifests. `.secrets/`, SSH administration scripts, and blog deployment infrastructure never enter the
research repository.

## Verification

Formal Release archives have adjacent `.sha256` files but are not committed to the main Git history.
Corresponding analysis scripts check raw-log steps, start/end events, intervention schedules, validation
intervals, and failure records. Any manually edited result must be saved separately with provenance.
